## 0. TL;DR — the 3 best integration paths, ranked by risk

### Path A — **Viewer-first, Lux3D for hero assets, Aholo-generated 3DGS world** (LOWEST RISK) ✅ recommended
- `npm i @manycore/aholo-viewer` (MIT, v1.11.0) — no API key, no credits, no rate limit for the viewer itself.
- Load a 3DGS scene (`.ply`/`.spz`/`.sog`) **and** GLB meshes generated by Lux3D **into the same `Scene3D`** — this is officially supported and demonstrated (see §3.3).
- Walk around with voxel collision by copying the official MIT `walk-demo.ts` example (see §3.5).
- Get the 3DGS room either from the Aholo **World API** (`/world/v1/reconstructions` or `/world/v1/generations`, return `plyPath`/`spzPath`) or from an existing Aholo public sample.
- **Risk:** low. **Main dependency:** you need one 3DGS scene + its voxel collision pair (§3.6); the voxel data is *not* provided by the World API and must be generated with `splat-transform`.

### Path B — **Lux3D web UI only (no API), viewer for the runtime** (MEDIUM RISK)
- Hackathon rules make Lux3D mandatory but Aholo API optional. You can generate GLB/PBR assets by hand in the Lux3D web editor, download them, and ship them as static files.
- **Risk:** manual, not reproducible, and free-tier export rights are unclear (§2.3 — "Export in all supported formats" and "Commercial use of generated models" are listed as **Pro** benefits). Fine for a demo, bad for an automated pipeline.

### Path C — **Full Aholo API pipeline** (HIGHEST RISK)
- `POST /lux3d/v1/generate/img-to-3d/task/create` → poll `GET /lux3d/v1/generate/task/get` → download GLB → feed to viewer.
- **Risks, all verified:** credit-based billing (`insufficient credits`, BIZ_11003 / BIZ_24002), per-account generation concurrency cap (`GENERATION_CONCURRENCY_LIMIT_EXCEEDED`), global task rate limit (429 / BIZ_11001), **result URLs expire after 2 hours**, and the declared gateway is the **China** host `https://api.aholo3d.cn` while the docs you're reading are the global `labs.aholo.ai`. Whether a global API host exists: **[UNVERIFIED]**.

### Biggest technical risk (single answer)
> **Getting a 3DGS scene that is both *loadable* and *walkable*, without a licensing landmine.**
> The open-source viewer renders splats fine, but a splat has no collision geometry. Collision requires `voxel-meta.json` + `voxel.bin` generated by `splat-transform`'s `Voxel` task — the Aholo World API does **not** return voxel data, and **InteriorGS does not ship it either**. Additionally **InteriorGS is a gated dataset under a non-commercial, research/education-only license with a no-redistribution clause** (§4.1) — do not build a prize submission on it without accepting that constraint.

### 1.5 The 3 endpoints that matter most, in exact detail

#### (1) `POST /lux3d/v1/generate/img-to-3d/task/create` — image(s) → 3D object
- **Auth:** `Authorization: <api key>` (no Bearer)
- **Request body** (`lux3d_ImgTo3dRequest`):

| Field | Type | Required | Notes |
|---|---|---|---|
| `img` | string | one of `img`/`imgs` | Single image URL. **Exactly one** of `img`/`imgs` must be provided. |
| `imgs` | string[] | one of `img`/`imgs` | 1–32 image URLs. First image = primary reference. **Requires explicit `version`.** |
| `version` | `"G1"` \| `"G1-Turbo"` | no | Omit → server default. Docs recommend passing explicitly. |
| `faceCount` | integer 10000–300000 | no | default 300000. **PLY output ignores this.** |
| `outputFormat` | array of `zip`\|`glb`\|`ply` | no | G1 always returns ZIP+GLB and adds PLY if requested. G1-Turbo returns only what you ask; empty/omitted → ZIP. |
| `enablePbr` | boolean | no | default `true`. **Only effective for G1-Turbo with Mesh**: true → PBR mesh, false → white model. Ignored for G1 and PLY-only. |
| `aiPredictSize` | boolean | no | omitted/true → AI size prediction + scaling enabled. |

- **Response** (`lux3d_TaskCreateResponse`): `{ "f": null, "c": "0", "m": "", "d": 1256173 }` where `d` is the integer `taskid`.
  - Error: `c` is `"-1"` for param errors, or a business code such as `GENERATION_CONCURRENCY_LIMIT_EXCEEDED`.
- **Official sample body:**
```json
{ "version": "G1-Turbo",
  "imgs": ["https://.../multiview_input_1.png", "https://.../multiview_input_2.png"],
  "outputFormat": ["glb"], "faceCount": 300000, "enablePbr": true }
```

#### (2) `GET /lux3d/v1/generate/task/get` — poll any Lux3D task
- **Query:** `taskid` (integer, int64, required)
- **Response** (`lux3d_TaskQueryResponse`): `{ f, c, m, d }` with `d` = `lux3d_TaskQueryData`:
  - `taskId` (int64)
  - `status` (int): **0 init, 1 running, 3 success, 4 failed, 6 cancelled**
  - `outputs`: array of `{ content: string }`
- **Result URL lifetime: 2 hours** (stated in the operation description: "结果 URL 有效期为 2 小时").
- **`content` per task type** (verbatim table from the operation description):

| Task type | Result format |
|---|---|
| Multimodal single image | one image URL |
| Multimodal four-view | JSON array string of 4 image URLs, order `FRONT_THREE_QUARTER, OPPOSITE_THREE_QUARTER, SIDE, BACK` |
| **G1 img/text → 3D** | file URLs in order **ZIP, GLB**; +PLY if requested |
| **G1-Turbo img/text → 3D** | only the requested formats; ZIP if none requested |
| Material repaint | ZIP, GLB, USDZ, OBJ ZIP, FBX ZIP (in that order) |
| Multi-format export | ZIP, GLB, USDZ, OBJ ZIP, FBX ZIP, STL, 3MF (in that order) |
| Part split | one GLB URL |
| Articulation + animation | `d.outputs[0].content` = file URL, format not fixed |
| Humanoid auto-rig | rigged GLB URL; failure may return JSON containing `error` |
| Humanoid retarget | JSON string containing `actions` |

- Unrequested optional formats may come back as the literal string `NOT_REQUESTED` — **not a URL**. JSON-string results must be parsed before reading fields.

#### (3) `POST /world/v1/reconstructions` — photos/video → 3DGS world
- **Request body** (`world_CreateWorldRequest`), required: `resources`, `scene`, `taskQuality`.

| Field | Type | Notes |
|---|---|---|
| `name` | string | display name |
| `cover` | string | optional cover image URL |
| `resources` | array, min 1 | `{ url, type }`; `type` ∈ `image` (`.jpg/.jpeg/.png/.webp`), `video` (`.mp4/.mov`), `insv` (Insta360 `.insv`) |
| `useMask` | boolean | matting on/off |
| `taskQuality` | `low` \| `normal` \| `high` | "极速预览 / 标准 / 专业" |
| `scene` | `model` \| `space` | `model` = object scene, `space` = indoor scene |

> **Hard input rule:** if any `type=image` (or omitted `type`, which counts as image) is present, there must be **at least 20 image resources**. Providing only `video`/`insv` bypasses this rule.

- **Response:** `world_WorldAsyncOperation` = `{ worldId: "A1b2C3d4E5" }`
- **Poll:** `GET /world/v1/{worldId}` → `world_WorldDetail`:

```
{ worldId, name, cover, scene, createTime, updateTime,
  status,                 // PENDING|PREPROCESSING|RUNNING|SUCCEEDED|FAILED|CANCELED|TIMEOUT|REJECTED
  progress,               // float 0.0..1.0
  assets: {
    splats:   { urls: { plyPath, spzPath, lodMetaPath } },   // lodMetaPath null unless LOD post-processing ran
    imagery:  { panoUrl },                                    // AI-generated worlds only
    semanticsMetadata: { upAxis }                             // "Y" or "Z" only — no object semantics
  } }
```

- **Note:** `semanticsMetadata` contains **only `upAxis`**. There is **no object-level semantic label list** returned by the World API. Object semantics only come from `SpatialUnderstanding` (and only from a `.ply` point cloud you supply).

- **Companion:** `POST /world/v1/generations` (SpatialGen) takes `{ name, cover, resources?, prompt? }`; at least one of `resources`/`prompt`; **at most 1 image**; indoor is mature, **non-indoor is explicitly Beta**.

#### Bonus — `POST /spatial-understanding/v1/tasks` (the semantics endpoint)
- Body: `{ inputFileUrl (required, `.ply` only, indoor point cloud), transformationMatrix? (4×4, column-vector `p'=Tp`, translation in **4th column**, right-handed, Z-up, metres, ScanNet alignment) }`
- Response: `{ taskId }`; poll `GET /spatial-understanding/v1/tasks/{taskId}`
- Status: `PENDING | RUNNING | SUCCEEDED | FAILED | TIMEOUT`
- Result: `result.resultSslUrl` → **UTF-8 plain-text DSL**, one entity per line, **server does not return parsed JSON**:
```
wall_0=Wall(1.6857,-4.4625,0.0,4.6798,-4.4474,0.0,2.73,0.0)
door_0=Door(wall_0,3.1734,-4.4550,1.05,1.3852,2.1)
window_0=Window(wall_4,5.6622,-1.0338,1.65,0.6883,1.5)
bbox_0=Bbox(carpet,-3.009,4.371,-1.401,-1.5708,5.718,6.734,0.109)
```
- `Bbox` format: `Bbox(class, px, py, pz, angle_z, scale_x, scale_y, scale_z)` — sizes are **full sizes, not half sizes**. Parsing hint from the docs: `class` may contain spaces (e.g. `dining chair`), so **take the last 7 comma-separated values as numbers and the left-hand remainder as `class`**. Unknown `Type` values must be skipped, not fatal.
- ~60 known classes are enumerated in the spec (chair, sofa, carpet, coffee table, wardrobe, bed, television, refrigerator, …).
- **Billing:** "受理成功即扣减积分" — credits are deducted on acceptance.

### 1.6 Async / polling patterns (three different conventions — do not mix them up)

| Family | Create returns | Poll | Terminal signal |
|---|---|---|---|
| **Lux3D** | `{f,c,m,d}` where `d` = int taskid | `GET /lux3d/v1/generate/task/get?taskid=` | `d.status`: 0/1 running, **3 success**, 4 failed, 6 cancelled |
| **World + SpatialUnderstanding** | `{worldId}` / `{taskId}` (string) | `GET /world/v1/{worldId}` / `GET /spatial-understanding/v1/tasks/{taskId}` | `status` string enum, `SUCCEEDED` |
| **RenderCloud** | no separate poll URL: submit with `requestId`+`usdContent` → HTTP **202** `{operationId, done:false}` | **same endpoint**, resend with `operationId` set | `done:true` + `result.taskId`/`resultUrl`, or `done:true`+`error` |

**RenderCloud realtime streaming** (relevant if you want cloud-rendered 3DGS+mesh compositing):
- `POST /rendercloud/v1/streams` → poll until `status === "ACTIVE"`; `result` contains `{host, nodeId, streamId, token}`; poll interval recommended 2 s, timeout 120 s.
- Then connect `wss://{host}/streaming/ws/session?nid={encodeURIComponent(nodeId)}&token={encodeURIComponent(token)}`, set **`ws.binaryType = 'blob'`**, and on `onopen` immediately send `{"type":3,"slaveInit":{"masterStreamingId":"{streamId}","receiveImage":true}}`.
- Server sends JSON status strings (`code` `"0"` = ready; `"1000"` node full; `"1001"` init failed; `"1003"` slave exceeded; `"2001"`/`"2002"` render errors that **do not** drop the connection) and **binary JPEG Blobs**.
- Close order matters: `ws.close()` **then** `DELETE /rendercloud/v1/streams/{sessionId}`.
- `usdContent` = `Base64(UTF-8(USDA plain text))`. Cloud rendering is fixed **Z-up and 1 unit = 1 mm**, max render edge 4500 px by default.

## 2. AHOLO LUX3D (`lux3d.aholo.ai`)

### 2.1 What it is
> "Aholo Lux3D is an AI 3D foundation model developed in-house by Manycore. It converts images or text descriptions into 3D Gaussian models for quick previews, then into refined models with geometry and PBR materials for rendering, editing, and production."
> — [lux3d.aholo.ai/lux3d/home](https://lux3d.aholo.ai/lux3d/home)

Four documented stages: **(1)** input a clear product image or a text description → **(2)** generate a **3D Gaussian preview** to verify appearance → **(3)** generate colour + **PBR material** properties and bake → **(4)** use in production.

### 2.2 Input types, output, and timing

### 2.4 Credit costs — published but ambiguous ⚠️
The pricing page publishes a credit table, but the extracted markdown **merges two numeric columns**, so several rows are unreadable. **Do not rely on these numbers without re-reading the live page.** What appears stable:

### 3.2 Minimal getting-started (vanilla, no three.js)

```bash
npm install --save @manycore/aholo-viewer
npm install --save-dev vite typescript
```
```ts
// index.ts  — verbatim pattern from https://aholojs.dev/llm/manual/getting-started.md
import {
    createViewer, setViewerConfig, PerspectiveCamera, BackgroundMode,
    Vector3, Color, SplatLoader, SplatUtils,
} from '@manycore/aholo-viewer';

const SPLAT_URL = 'https://holo-cos.aholo3d.cn/aholo-opensource/gs_file/bear/bear.3d71a266.sog';

const container = document.createElement('div');
container.style.width = '500px';
container.style.height = '500px';
container.style.display = 'block';
document.body.appendChild(container);

async function createScene() {
    const viewer = createViewer('example-viewer', container, {});
    const camera = new PerspectiveCamera(60, 1, 0.1, 2000);

    const resp = await fetch(SPLAT_URL);
    const buffer = await resp.arrayBuffer();
    const data = await SplatLoader.parseSplatData(
        SplatLoader.SplatFileType.SOG,
        new Uint8Array(buffer),
        SplatLoader.SplatPackType.Compressed,
    );
    const splat = await SplatUtils.createSplat(data);

    // OpenCV-style 3DGS data is -Y up.
    camera.up.set(0, -1, 0);
    camera.position.set(-1.5, -0.5, 0);
    camera.lookAt(new Vector3(0, 0, 0));

    viewer.getScene().add(splat);
    viewer.setCamera(camera);
    setViewerConfig(viewer, {
        pipeline: {
            Background: {
                background: { active: BackgroundMode.BasicBackground, basic: { color: new Color(0, 0, 0) } },
                ground: { enabled: false },
            },
            Splatting: { enabled: true },
            TAA: { enabled: false },
        },
    });

    const render = () => viewer.render();
    viewer.requestRenderHandler = () => requestAnimationFrame(render);
    requestAnimationFrame(render);
}
createScene();
```

**No three.js involved.** Aholo Viewer is its own WebGL/WebGL2 engine with its own math, scene graph, materials and loaders. You do **not** need three.js, and there is no documented three.js interop.

Two integration rules the official skill file stresses:
1. Put DOM event listeners on the **container** you passed to `createViewer`, **never** on the engine canvas (the engine may replace the canvas).
2. Never hold a persistent reference to the engine canvas.

### 3.3 ⭐ CRITICAL — Can arbitrary meshes (GLB/glTF) be composited with a 3DGS scene? **YES.**

**This is officially supported and demonstrated, not a hack.** Three independent pieces of evidence:

**(a) The product statement.** From the official manual:
> "Aholo-Viewer is a general-purpose renderer for **standard Mesh and 3DGS content**."
> — [basic-concepts](https://aholojs.dev/llm/manual/basic-concepts.md)

**(b) A shipped glTF loader.** `GLTFLoader.loadGLTF` is a public export, alongside `DracoLoader`:
```ts
// https://aholojs.dev/llm/api/gltf-loader/functions/load-gltf.md
loadGLTF(data: string | ArrayBuffer, config: LoaderConfig): Promise<ParseResult>
```
`LoaderConfig` accepts a `textureLoader` (e.g. `downloadTexture`). `ParseResult` yields `scene`, `animations`, `skeletons`.

**(c) The official walk demo puts both in ONE scene.** From `website/src/content/examples/walk-demo.ts`:
```ts
this.scene = this.viewer.getScene() as Scene3D;
this.scene.add(this.splatLayer);        // 3DGS layer
this.splatLayer.add(splat);             // ... 3DGS object
this.scene.add(this.characterRoot);     // mesh container
this.characterRoot.add(model);          // GLB loaded via loadGLTF(...)
```

**How to do it (the mechanism):** everything is an `Object3D`; create the splat via `SplatUtils.createSplat(...)`, create/load meshes via `new Mesh(geometry, material)` or `loadGLTF(...)`, then `viewer.getScene().add(...)` both. Transforms (`position`/`rotation`/`scale`) work the same on both.

**The one real caveat (verified):**
> "gltf-loader: Loads models described by the glTF/glb format. Because Aholo-Viewer currently **primarily renders with Phong materials, PBR-based glTF materials may not be converted completely**."
> — [basic-concepts, Model Support](https://aholojs.dev/llm/manual/basic-concepts.md)

So: **geometry, transforms, textures and skeletal animation come through; full PBR material fidelity does not.** If your Lux3D assets are PBR-heavy, expect to re-map them to `MeshPhongMaterial`/`MeshBasicMaterial`, or live with degraded shading. Plan for this — it is the most likely visual surprise.

**Recommended approach** if you need physically-correct PBR compositing: use **Aholo RenderCloud** (`/rendercloud/v1/jobs` offline, or `/rendercloud/v1/streams` realtime), which composites 3DGS and high-fidelity meshes server-side via OpenUSD and streams the frame — see the marketing claim on [aholojs.dev home](https://aholojs.dev/en-US/) ("3DGS and high-fidelity meshes, rendered together in real time") and the `RenderCloudOpenUSDGuide` tag in the spec. Trade-off: server dependency, credits, network.

### 3.6 Walk mode + voxel collision — **concrete and important**

**Key structural fact: `ViewerWalkMode` and `VoxelCollision` are NOT package exports.** They are absent from `/llm/api/index.md` (154 symbols), and `walk-demo.ts` *defines and exports them itself*. **The walk system is MIT example code you copy — not an SDK you call.**

- Source: `website/src/content/examples/walk-demo.ts` (≈85 KB) — mirrored at `https://aholojs.dev/llm/examples/walk-demo.md`.
- Header: *"Walk demo: splats + collision + ViewerWalkMode. Derived from SuperSplat Viewer (MIT) and adapted for Aholo Viewer, voxel collision, and the website runtime."*
- Exports: `class VoxelCollision`, `class ViewerWalkMode`, `class WalkThirdPersonCharacter`, `class WalkDemoScene`.
- Tunables baked into the file: `WALK_CAPSULE_HEIGHT = 1.5`, `WALK_CAPSULE_RADIUS = 0.12`, `WALK_HOVER_HEIGHT = 0.2`, `WALK_EYE_HEIGHT = capsule − 0.1 − hover`, `WALK_GRAVITY = 9.8`, `WALK_SIMULATION_STEP_SECONDS = 1/60`, `MAX_SUBSTEPS = 10`.

**Loading the collision data at runtime** (the demo's own pattern):
```ts
const [jsonRes, binRes] = await Promise.all([fetch(jsonUrl), fetch(binUrl)]);
const metadata = JSON.parse(await jsonRes.text());
const bytes = new Uint8Array(await (await fetch(binUrl)).arrayBuffer()); // see note
const allU32 = new Uint32Array(bytes.buffer, bytes.byteOffset, Math.floor(bytes.byteLength / 4));
const nodes = allU32.slice(0, metadata.nodeCount >>> 0);
const leafData = allU32.slice(metadata.nodeCount >>> 0,
                             (metadata.nodeCount >>> 0) + (metadata.leafDataCount >>> 0));
walk.loadVoxelCollision(metadata, nodes, leafData);
```
Then queries: `collision.queryRay(x, y, z, dx, dy, dz, maxT)` (direction need not be normalised) and `collision.queryCapsule(x, centerY, z, halfHeight, radius, pushOut)`.

**Ready-made collision datasets you can point at today** (the demo's own presets — indoor + outdoor, with voxel pairs):
```
https://holo-cos.aholo3d.cn/aholo-opensource/gs_file/room/voxel/10c88df3/collision.voxel-meta.json
https://holo-cos.aholo3d.cn/aholo-opensource/gs_file/room/voxel/10c88df3/collision.voxel.bin
https://holo-cos.aholo3d.cn/aholo-opensource/gs_file/juguo/voxel/309eccc1/collision.voxel-meta.json
https://holo-cos.aholo3d.cn/aholo-opensource/gs_file/juguo/voxel/309eccc1/collision.voxel.bin
```
…plus matching splats under `.../room/` and `.../juguo/`, and GLB characters at `.../misc/man-final.755ce8ea.glb` / `.../misc/robot.0765006a.glb`. **Reusing these is the fastest path to a working walkable demo.**

**Voxel data format** ([physics-collision](https://aholojs.dev/llm/manual/physics-collision.md)): Laine–Karras sparse voxel octree, shared with PlayCanvas. `voxel-meta.json` (schema `version: '1.2'`) + `voxel.bin[.gz|.zst]`; optional `collision.glb`. `leafSize = 4` (64 occupancy bits/leaf); solid leaf marker `0xFF000000`; compact encoding magic `0x31424356` (`VCB1`).

> **Documentation gap I want to flag:** the manual states plainly that *"`splat-transform` only **generates** voxel data. Ray tests and depenetration are implemented at **runtime** after loading the octree."* Combined with the fact that `ViewerWalkMode` is example code, **there is no supported drop-in collision API** — you inherit and adapt the demo.

### 4.5 Is `3dgs_compressed.ply` directly loadable by aholojs?

**Very likely yes — but I could not test it end-to-end because the file is gated. Marked [UNVERIFIED-ish: strong circumstantial evidence, no executed load].**

Evidence for:
- Aholojs supports `SplatFileType.PLY` (value `0`) and `SplatPackType.Compressed` (value `1`) — both are public enums (§3.4).
- InteriorGS explicitly states its PLY is **"compressed using the SuperSplat method"**. - Coordinate conventions match: InteriorGS is `XYZ = (Right, Back, Up)`; the Aholo getting-started sample sets `camera.up.set(0, -1, 0)` for "OpenCV coordinates", which is the same right/back/up family.

**How to load it once you have the file:**
```ts
const buf = new Uint8Array(await (await fetch('/assets/interiorgs/0001_839920/3dgs_compressed.ply')).arrayBuffer());
const data = await SplatLoader.parseSplatData(
    SplatLoader.SplatFileType.PLY,
    buf,

);
const splat = await SplatUtils.createSplat(data);
viewer.getScene().add(splat);
```
**De-risking step (do this first):** run `SplatLoader.detectSplatFileType(buf)` from the public API and check what it reports before wiring `createSplat`. If `Compressed` is rejected, fall back to converting the PLY offline with `@manycore/aholo-splat-transform` (which is the same engine as Aholo's own `splat-transform`) or `@playcanvas/splat-transform` to `.spz`/`.sog`, both of which aholojs loads natively.

### 4.6 Can semantic instance labels place objects programmatically?

**Yes in principle, from two possible sources:**

1. **`structure.json` `ins[]`** — gives `label`, `position` (world-frame bbox centre) and `size`. This is directly usable: transform a GLB to that position, scale to `size`. Format is documented in the README.
2. **`labels.json`** — per-object class + instance ID + 8-corner oriented bbox. Richer (gives orientation), but exact key names **[UNVERIFIED]**.

**Caveats:**
- This is exactly the mechanic that makes a "spot the object that doesn't belong" game work — you can read real object centroids and place your AI-generated "foreign" object among authentic furniture.
- **Coordinate-system mismatch must be handled explicitly:** InteriorGS `structure.json` is documented **Z-up**, while InteriorGS **3DGS PLY** is documented `XYZ = (Right, Back, Up)`. The README describes two different conventions in two sections. **Reconcile this empirically before trusting placements** — do not assume one transform works for both.
- You can also get object semantics from **Aholo's own** `SpatialUnderstanding` API (`.ply` point cloud → `Bbox(class, px,py,pz, angle_z, scale_x,scale_y,scale_z)`), which hands you a ready Z-up, metre, right-handed convention — **possibly cleaner than fighting InteriorGS's dual conventions**, and it is a first-party hackathon tool.

### 5.4 Generating the missing voxel collision data (the critical gap)
Neither the Aholo World API nor InteriorGS returns voxel occupancy. Two tools produce it, both MIT, both derived from the PlayCanvas lineage Aholo's own docs cite:

| Tool | Package | Version |
|---|---|---|
| Aholo's own | **`@manycore/aholo-splat-transform`** | **2.0.2**, MIT |
| Upstream | `@playcanvas/splat-transform` | 3.10.3, MIT |

`Voxel` task parameters (from [splat-transform manual](https://aholojs.dev/llm/manual/splat-transform.md)):

| Parameter | Default | Note |
|---|---|---|
| `input` / `output` | required | splat resource key / voxel output directory |
| `voxelResolution` | `0.05` | voxel edge length in input units |
| `opacityCutoff` | `0.1` | 0–1 occupancy threshold |
| `backend` | `gpu` | `gpu \| cpu`; falls back to CPU with a warning if Vulkan init fails |
| `box` | ±100 | `{ minCorner, maxCorner }` |
| `collisionMesh` | `false` | `true`⇒`smooth`; `faces` = voxel surfaces, `smooth` = marching cubes |
| `floorFill`, `floorFillDilation` | `false`, `0` | fill up from grid bottom to make a floor |
| `navSeed`, `navExteriorRadius`, `navCapsule` | unset | navigation fill; capsule nav when `height>0` and `navSeed` set |
| `compression` | `none` | `none \| gzip \| zstd` |
| `nodeEncoding` | `raw` | `raw \| compact` |

JS API:
```js
import { run } from '@manycore/aholo-splat-transform';

await run({
  version: 1,
  tasks: [
    { id: 'read',  type: 'Read',  config: { inputs: ['input.ply'], output: 'source' } },
    { id: 'vox',   type: 'Voxel', config: { input: 'source', output: 'voxels/',
                                            voxelResolution: 0.05, opacityCutoff: 0.1,
                                            collisionMesh: 'smooth', floorFill: true } },
  ],
}, { cwd: process.cwd(), signal: controller.signal });
```
> The package's `bin` field is `null` in the npm manifest, so **prefer the JS API over a CLI binary** for `@manycore/aholo-splat-transform`. The separate `@playcanvas/splat-transform` also exposes a CLI.

**Note the practical implication:** voxel generation is CPU/GPU heavy, so do it **once at build time**, commit the `voxel-meta.json` + `voxel.bin` into your static assets, and let the browser only *read* them (which is all `walk-demo.ts` does).

## 6. Recommended concrete architecture (Path A)

```
[BUILD TIME — offline, one-off]
  InteriorGS scene (after gate approval) or Aholo World API output
        └─ 3dgs_compressed.ply ──► @manycore/aholo-splat-transform Voxel task
                                   └─► voxel-meta.json + voxel.bin  (commit these)
  Lux3D (web UI or API) ──► "foreign object" GLB (PBR → remap to Phong)

[RUN TIME — browser, zero API keys, zero credits]
  @manycore/aholo-viewer
    Scene3D
      ├── SplatLayer ── SplatUtils.createSplat(parseSplatData(PLY, Compressed))
      ├── ForeignObjects ── GLTFLoader.loadGLTF(glb) → new Mesh / MeshPhongMaterial
      ├── AmbientLight + DirectionalLight ×4
      └── ViewerWalkMode (copied from MIT walk-demo.ts)
            └── VoxelCollision(metadata, nodes, leafData)
                  ├── queryRay()      → crosshair picking / "mark the anomaly"
                  └── queryCapsule()  → WASD movement + wall collision
```

Why this is the low-risk choice: **no API key, no credits, no rate limits, no 2-hour URL expiry, no network dependency at runtime, and every non-obvious piece is MIT-licensed code you can read.** Aholo Lux3D still occupies the required central role (it generates the anomalous objects), and Aholo API is available as an optional stretch.

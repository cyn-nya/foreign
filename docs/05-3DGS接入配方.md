# 3DGS 接入配方（已实测验证）

> 这份文件里的每条结论都有 `tools/probe.mjs` 的输出作为证据。
> **不要凭直觉改这些参数** —— 下面每一条都是踩过坑之后才定下来的。
> 复现命令：`npm run build && node tools/probe.mjs --scene room`

场景：官方开源室内重建 `scene.7c26e842.spz`（63.0 MB）
相机位姿：官方 walk demo 的 `WALK_DEMO_INDOOR_POSE`

---

## 1 · 结论速查

| 项目 | 正确做法 | 不这么做会怎样 |
| --- | --- | --- |
| 取数据 | **自己 `fetch` 拿 `Uint8Array` 再传给 `parseSplatData`** | 传 URL 时耗时 **55.8s**；自己 fetch 只要 **11.8s** |
| `packType` | `SplatLoader.SplatPackType.Compressed` | 解码出的 splat 是错的，画面糊成一片 |
| 背景 | `BackgroundMode.BasicBackground` + 纯黑 | 默认天空背景占满画面，看不到房间 |
| TAA | `TAA: { enabled: false }` | 静帧被跨帧混合，糊向背景 |
| 剔除 | `drivenCullingConfig` 全关 | splat 被大量剔除，只剩薄雾 |
| 相机 | 自建 `PerspectiveCamera(60, aspect, 0.1, 1_000_000)` | 默认 far 太小，世界单位 >1e3 的扫描被裁掉 |
| `maxShDegree` | `3`（官方值） | 不是性能问题：sh=3 与 sh=0 解码只差 0.4s |

## 2 · 根因：为什么之前看到的是"平滑白雾"

第一版探针的统计是 `mean≈207`、`edge≈0.87`（灰阶/像素），
在**每一个**视角、甚至换一个资产（bear）上都是同样的数字 ——
相同的边缘能量说明那不是场景，是噪声/背景。

真正的原因有四个叠加，缺一条都还是糊的：

1. **`packType` 没传** → splat 数据解码错误
2. 背景还是默认天空 → 亮的平滑渐变占满画面
3. `TAA` 默认开着 → 单帧渲染被跨帧平均
4. `drivenCullingConfig` 默认开着 → splat 被剔除

修好之后同一视角（`spawn-forward`）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| `edge`（灰阶/像素） | 0.87 | **9.54** |
| 精确颜色数 | ~500 | **11525** |
| PNG 体积 | 77 KB | **826 KB** |
| 对照（移除 splat） | mean 210（≈有 splat） | mean **1.6**（纯黑） |

最后一行是决定性证据：移除 splat 后画面变成纯黑，说明现在**画面完全由 splat 构成**。

## 3 · 关键代码

```ts
// 1. 自己的相机 —— 默认相机的远平面装不下这种扫描
const camera = new PerspectiveCamera(60, w / h, 0.1, 1_000_000);
camera.enableFrustumCulling = false;
camera.enableDetailCulling = false;
viewer.setCamera(camera);

// 2. 背景、TAA、剔除 —— 三样都必须显式关掉
setViewerConfig(viewer, {
  pipeline: {
    Background: {
      background: {
        active: BackgroundMode.BasicBackground,
        basic: { color: new Color(0, 0, 0), alpha: 1 },
      },
      ground: { enabled: false },
    },
    Splatting: { enabled: true },
    TAA: { enabled: false },
  },
});

// defaultViewport 不在公开类型里，官方 walk demo 也是 `as any` 拿的
const culling = (viewer as any).defaultViewport?.drivenCullingConfig;
if (culling) {
  culling.frustumCullingEnabled = false;
  culling.occlusionCullingEnabled = false;
  culling.detailCullingEnabled = false;
  culling.layersCullingEnabled = false;
  culling.triCullingEnabled = false;
}

// 3. 取数据：自己 fetch
const bytes = new Uint8Array(await (await fetch(url)).arrayBuffer());
const data = await SplatLoader.parseSplatData(
  SplatLoader.SplatFileType.SPZ,
  bytes,
  SplatLoader.SplatPackType.Compressed,
  { maxShDegree: 3, maxTextureSize: 8192 },
);
const splat = await SplatUtils.createSplat(data);
viewer.getScene().add(splat);
```

## 4 · 加载耗时实测

| 配置 | 下载 | 解码 | 合计 |
| --- | --- | --- | --- |
| 官方参数 `sh=3 pack=compressed` | 10.0s | **1.8s** | 14.3s |
| `sh=0 pack=compressed` | 7.8s | **1.4s** | 11.8s |
| `sh=0 pack=raw` | 25.3s | 0.9s | 26.2s |

**结论**：耗时几乎全在 **63 MB 的下载**上，解码只要 1~2 秒。
所以：
- **保留 `maxShDegree: 3`**（画质更好，只贵 0.4s）
- 优化方向是**把资产放到同源 / 更快的 CDN**，以及做一个真实的加载进度条
- 下载耗时抖动很大（7.8s ~ 25.3s），**必须有进度反馈**，不能只有转圈

## 5 · 扫描覆盖范围

重建扫描只包含采集设备真正看到过的区域。在 8 个候选站位各测 6 个朝向：

| 站位 | 有画面的朝向 |
| --- | --- |
| walk-pose (-4.148, 1.232) | 6/6 |
| centre (-1.0, 0.5) | 6/6 |
| grid-nw / ne / sw / se | 6/6 |
| north (-1.0, -5.0) | 6/6 |
| south (-1.0, 6.0) | 6/6 |

**结论**：房间中部一大片区域都有完整数据，玩家可以自由走动。
但**存在窄缺口**：从 walk-pose 朝 yaw≈167.6° 看是纯黑（别的朝向都好）。
摆放玩家初始位置时要避开这类朝向，或者接受偶发的黑边。

> 注意：第一次跑这个扫描时 8 个站位全是 0/6，那不是扫描的问题，
> 是 `tools/probe.mjs` 的 bug —— 对照实验 `control-no-splat` 把 splat
> **永久移出了场景**，之后的扫描全在拍空场景。已加 `__restoreSplat()`。

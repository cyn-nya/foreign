# FOREIGN · 异物

> 一间被 3D 重建的真实房间。每一层都有东西**不属于这里**。
> 在时间耗尽之前，把它们全部找出来。

参赛作品，**Manycore Aholo Global 3D AI Hackathon**。

**▶ 在线试玩：https://cyn-nya.github.io/foreign/**

---

## 一句话

把「空间重建」从**可浏览**变成**可玩**：真实房间只用 3DGS 重建一次，
此后所有变化都来自 **Aholo Lux3D** 生成的 3D 内容。

## 为什么这样设计

评审权重里 **30% 是 Manycore 工具使用 + 25% 是好玩**。所以最优解不是做一个
炫技 demo，而是让**玩法本身离不开 AI 生成的 3D 物件** —— 没有 Lux3D 就没有游戏内容。

| 设计决策 | 原因 |
| --- | --- |
| **一间房，无限层** | 美术成本 = 一间房。变化的是物件，不是场景。完成度天然高。 |
| **异常由生成物件供给** | Lux3D 是内容引擎，不是贴图库 → 工具分是「核心」而非「点缀」。 |
| **没资产也能玩** | 每个物件都有程序化占位模型；GLB 到位后按 key 自动替换。**缺资产永远不是崩溃。** |
| **一眼可判的规则** | 不需要背房间、不需要和上一层对比 —— 这条约束砍掉了整类设计。 |

## 玩法

第一人称走进一间真实重建的公寓。它看起来就是一个普通的家 —— 问题恰恰在这里。

准星对准，左键标记。**每层只有 3 次标记机会**：标对得分（剩余时间越多分越高），
标错扣 8 秒**并且**消耗一次机会。找齐下潜一层，时间归零或机会用尽则结束。

### 一条规则，一眼可判

**标记任何不可能出现在一个家里的东西。**

这条约束不是修辞，它决定了哪些机制能用：

> 我们**删掉了**「东西消失了」这类异常。它只有在记得原样的前提下才成立，
> 而玩家第一次进房间时没有参照物。任何需要「和之前对比」的异常都不能用。

现有 7 种异常，全部满足这条规则：

| 类型 | 内容 |
| --- | --- |
| `intrude` | 凭空多了一件 AI 生成的东西（Lux3D 资产） |
| `stare` | 一张脸悬在人的高度，**一直在看着你** |
| `shift` | 东西浮在半空 / 被钉在天花板 |
| `warp` | 尺寸或颜色被改了 |
| `twin` | 同一个东西出现了 3–5 个 |
| `invert` | 东西**倒挂**着，没有任何东西托着它 |
| `swarm` | 同一个东西出现了十几个，数不清 |

```
Vite 8 · TypeScript 7 · three.js 0.186 · @manycore/aholo-viewer 1.11 · Vitest · Playwright
```

### 两个渲染后端，一套玩法

| 后端 | 入口 | 说明 |
| --- | --- | --- |
| **真实房间** | `/`（默认） | `@manycore/aholo-viewer` 渲染官方开源 3DGS 场景，配官方体素碰撞场 |
| 程序化房间 | `/classic.html` | three.js 搭的同一套房间，用于对比与回退 |

两者共享 `src/game/`（规则、目录、类型）—— **那一层不含任何渲染依赖**，
所以同一套关卡生成逻辑被两个后端使用，也被全部单测覆盖。

```
src/
  game/            纯逻辑，不含 three.js
    types.ts       类型
    catalog.ts     程序化房间的真相：墙体、家具槽位、生成点、AI 异物定义
    rules.ts       种子随机、楼层生成、判定、计分
  viewer/
    VoxelCollision.ts  八叉树体素碰撞（取自 Aholo 官方示例，附出处）
    voxel.ts           胶囊体解算与坐标换算
  splat/           真实房间后端
    main.ts        循环、状态机、全部界面
    SplatScene.ts  viewer 配置 + splat 加载 + 体素场
    SplatPlayer.ts 第一人称手感（阻尼、蹲伏、头部摆动）
    SplatRoom.ts   异常摆放、注视者动画、拾取
    audio.ts       靠近异常的持续音 + 标记音
  aholo/client.ts  Aholo API 客户端（生成异物资产）
tools/             验收与构建工具（见下）
```

## 验收

```bash
npm run verify
```

这不是「截图看看」，而是 **typecheck → 85 个单测 → 构建 → 四个无头实机验收**：

| 步骤 | 内容 |
| --- | --- |
| `voxel:check` | 10 项，体素场与官方文件逐字节核对 |
| `test` | 85 个单测：种子可复现、难度曲线、锚点合法性、判定与计分 |
| `splat:check` | 5 项，splat 加载与拾取 |
| `splat:shoot` | **29 项**，真实房间：默认入口、行走、碰撞对照、玩法闭环、注视者、音效、新异常类型 |
| `shoot` | 15 项，程序化房间：每个视角确实渲染出家具、每件家具都看得到 |
| `deploy:check` | 7 项，**构建产物在子路径下真的能跑** |

### 两条贯穿始终的检查原则

**1 · 断言必须有两侧边界。** 「走不过去」和「根本没动」在数值上无法区分 ——
一个永远不动的行走者也能满足「没有走出房间」。所以碰撞检查同时断言：
有碰撞时走不远（8.36 m），**关掉碰撞后必须走得很远**（34.83 m）。

**2 · 对照是必需项，不是加分项。** 「异常朝向玩家」只有在
「地面物体**不**转头」也成立时才有意义 —— 否则整个房间一起转也会通过。

这套检查真的抓到过 bug，包括一个只有演示链接才会触发的崩溃：
`?autostart=1` 时 `let plan` 还在暂时性死区（菜单路径永远碰不到，因为按钮回调跑得晚）。

## 关卡正确性是被测出来的

真实房间的 9 个摆放锚点不是手填的，是**相机实测**出来的：

```
0.25 m 网格向下投射 → 219 个候选面
  → 楼层高度带筛选   → 112
  → 胶囊体可站立     →  97
  → 排除离入口 1.6 m 内 → 49
  → 最远点贪心取 9 个
```

`npm run anchors:build` 可重跑。数据落在 `data/room-anchors.json`。

## Aholo 集成

- **Aholo Lux3D（必需）**：生成异物资产。prompt 写在 `data/foreign-assets.json`。
  **两条路，任选其一** —— 网页版不需要 API key：

  ```bash
  # 有 key：一条命令跑完 21 个（生成 → 轮询 → 下载 → 记录来源）
  npm run assets:generate

  # 没有 key：在 https://lux3d.aholo.ai/lux3d/home 用网页版逐个生成并下载，
  # 然后把下载目录交给这个工具，它会校验、命名、归位并记录来源
  npm run assets:import -- ~/Downloads
  ```

  `assets:import` 会交互式列出每个 key 对应的 prompt，你按着读就能对上；
  也可以用 `--order`（按目录顺序）或 `--set duck=file.glb`。

- **Aholo Viewer / 3DGS（已用）**：真实房间后端，见 `docs/05-3DGS接入配方.md`。
- **Aholo API（可选）**：`src/aholo/client.ts`，用于批量生成。

生成结果没有统一的比例和轴心，所以会按每个资产的目标高度归一化、
并把底面重新对齐到 y = 0 —— 否则「一盒牛奶」会以两米高进来。

`npm run assets:check` 会断言「哪些资产真的来自 Lux3D」。
**这不是多余的**：原先的判断只看 `.glb` 是否存在，而占位模型写在同样的路径上，
于是填上 key 之后工具会报「无事可做」并跳过全部 21 个 —— 静默失效。

## 已知限制

- **Lux3D 资产尚未生成**：目前用的是 21 个程序化占位模型，游戏完整可玩。
  生成需要 API key，跑 `npm run assets:generate` 即可替换，不改动任何玩法逻辑。

  传输层已经**对着真实接口验证过**：用一个故意无效的 key 调用只读的
  `task/list`，服务器回的是 `invalid appKey` —— 它读到并解析了我们的认证头，
  只是值不对。这证明 base URL、endpoint 路径、认证头格式、信封解析、
  错误映射全部正确，**唯一缺的就是一个有效的 key 值**。

  `npm run assets:check` 会持续断言「哪些资产真的来自 Lux3D」。
  这不是多余的：原先的判断只看 `.glb` 是否存在，而占位模型写在同样的路径上，
  于是填上 key 之后工具会报「无事可做」并跳过全部 21 个 —— 静默失效，
  而且正好落在刚拿到 key 的人身上。
- **demo 视频帧率低**：录制机器没有 GPU，63 MB 的 splat 走软件渲染大约只有
  1–3 fps。瓶颈经测量是 CPU 侧的 splat 排序（640×360 并不比 960×540 快），
  不是填充率 —— 有显卡的机器上不是这样。

见 [docs/01-方向评估.md](docs/01-方向评估.md) 了解六个方向的完整评分与取舍。
